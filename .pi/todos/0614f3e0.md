Audit the current workspace for functionality that is mentioned in docs, examples, tests, config, CLI/help text, or code comments but is either not implemented, incomplete, or no longer needed. Remove unnecessary features and references so the repository is leaner and accurately reflects supported functionality.

Scope:
- Entire current workspace.
- No excluded areas.
- Focus especially on functionality outside the desired IMAP-only direction.

Known examples to remove/clean up:
- POP3-related functionality.
- Gmail-related functionality.
- Any other mail/provider functionality that is documented or partially present but not needed for IMAP support.

Guidance:
- The repository only needs IMAP functionality.
- Remove stale docs, dead code, unused config, examples, tests, or user-facing references for unsupported/unneeded features.
- If a documented-but-unimplemented feature is found and it is not obviously covered by the IMAP-only direction, ask before removing or implementing it.
- Do not implement missing non-IMAP features unless explicitly approved.

Expected outcome:
- A leaner repository.
- Docs and code accurately describe only supported/needed functionality.
- No stale POP3/Gmail or other unnecessary feature references remain unless explicitly approved.

Suggested steps:
1. Search the workspace for documented features and references across docs, examples, tests, config, CLI/help text, and code.
2. Identify items that are unimplemented, incomplete, or unnecessary.
3. Remove POP3/Gmail/non-IMAP functionality and references where appropriate.
4. For ambiguous features, ask before making changes.
5. Run relevant tests/checks if available.
6. Summarize removed areas and any remaining decisions needed.
