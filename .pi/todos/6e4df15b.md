## Context
Review found that MCP call paths route through `MailService` and enforce `allowed_folders`, but there are hardening opportunities around trusting connector-provided metadata and aggregate/provider folder semantics.

## Hardening ideas

- Validate connector-returned message metadata consistently:
  - Ensure `MessageSummary.folder_path` is allowed.
  - Ensure `MessageSummary.folder_token` decodes to the same `folder_path`.
  - Ensure `resource_uri` and `raw_resource_uri` folder token components match `folder_token` / `folder_path`.
- Apply equivalent validation for `MessageDetail` and attachment metadata/resource URIs.
- Add regression tests with a malicious/faulty fake connector returning mismatched folder paths/tokens/URIs.
- Consider documenting or mitigating aggregate mailbox behavior, e.g. `All Mail` may expose messages carrying labels/folders otherwise excluded if `All Mail` itself is allowed.
- Consider optional canonicalization/alias configuration if providers expose the same mailbox under multiple names.
