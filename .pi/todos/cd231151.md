Implement folder filtering semantics audited in TODO-e68b9633 and harden every search/read/resource/cache path against bypasses.

## Required Semantics

- `allowed_folders` is an exact allow-list: when set, only exact matching folders are accessible.
- `excluded_folders` overrides `allowed_folders` when both match.
- Folder matching is case-insensitive, preferably via `str.casefold()`.
- `allowed_folders=None` means all folders are allowed except excluded folders.
- Denied folders/messages must be indistinguishable from missing to users, while logging internal audit details.
- Denied folders must never be exposed through listings, search results, direct id/resource fetches, attachment paths, or cache hits.

## Implementation Plan

1. Add a central folder policy helper in the service layer.
   - Derive normalized allow/exclude sets from `settings.account.allowed_folders` and `settings.account.excluded_folders`.
   - Provide methods like `is_allowed(folder_path)`, `filter_folders(folders)`, and `assert_allowed(folder_path, operation, uid=None, attachment_id=None)`.
   - Log denied access internally with protocol, operation, folder, uid, and attachment id where available.
   - Raise the same public not-found exception shape used for missing folders/messages/attachments.

2. Enforce policy before every connector call and before every cache read.
   - `MailService.list_folders()` filters connector folder output.
   - `MailService.search_messages()` checks explicit `filters.folder` before searching.
   - `MailService._search_all_folders()` only considers policy-allowed selectable folders, including all-mail/archive heuristic selection.
   - `MailService.fetch_message()` decodes/checks folder token before `_cache.get()`.
   - `MailService.fetch_details_bulk()` checks every folder token before cache reads and bulk connector fetches.
   - `MailService._fetch_message_uncached()`, `fetch_raw_message()`, and `fetch_attachment()` check policy before connector calls.

3. Harden cache behavior.
   - Never return cache entries for denied folders.
   - Validate cached `MessageDetail.folder_path` is still allowed and matches the requested decoded folder token.
   - Ignore or purge stale cache rows that fail current policy/match validation.

4. Harden direct server/tool/resource access paths via service enforcement.
   - Verify these become protected by service checks:
     - `mail_fetch(ids=[...])`
     - normal `mail_fetch` search/list/read enrichment
     - `mail_download_attachment`
     - `mail://{folder_token}/{uid}`
     - `mail+html://{folder_token}/{uid}`
     - `mail+raw://{folder_token}/{uid}`
     - `mail+attachment://{folder_token}/{uid}/{attachment_identifier}`
     - `mail://folders`
     - `mail_debug_list_parts`
   - Do not rely on server-layer checks alone; service layer should be the primary enforcement boundary.

5. Fix protocol-specific bypasses.
   - Graph:
     - Direct `fetch_message`, `fetch_raw_message`, and `fetch_attachment` currently use `/messages/{uid}` independent of folder.
     - Either use folder-scoped Graph endpoints where possible or verify fetched message `parentFolderId` matches the decoded folder token and current policy before returning/caching data.
     - Raw and attachment fetches need equivalent parent-folder verification before bytes are returned.
   - POP3:
     - Treat `INBOX` as the only valid virtual folder.
     - Reject/404 non-INBOX folder tokens and enforce policy on `INBOX` before any `RETR`.
   - IMAP:
     - Keep readonly `SELECT` and `BODY.PEEK`; add policy enforcement above connector layer and avoid duplicating policy in IMAP unless useful for defense in depth.

6. Clarify Graph folder matching semantics.
   - Current `FolderInfo.path` is Graph's opaque folder id while roles are inferred from display name.
   - Decide whether `allowed_folders`/`excluded_folders` for Graph match folder ids only, display names only, or both.
   - Implement and document the chosen behavior. Prefer explicit, deterministic matching.

7. Add/adjust documentation.
   - Document exact/case-insensitive semantics.
   - Document excluded-overrides-allowed.
   - Document Graph folder identifier/display-name behavior.
   - Document denied access returning not-found-style behavior.

## Test Plan

- Config/env parsing:
  - `MAIL_ACCOUNT__ALLOWED_FOLDERS` is parsed.
  - `MAIL_ACCOUNT__EXCLUDED_FOLDERS` is parsed.

- Folder policy unit tests:
  - Case-insensitive exact matching (`INBOX` allows `inbox`, not `Inbox/Sub`).
  - Excluded folder overrides allowed folder.
  - `allowed_folders=None` plus exclusions works.
  - Empty allow-list behavior is defined and tested.

- Folder listing tests:
  - `mail://folders` hides disallowed folders.
  - Non-selectable handling remains unchanged except for filtering.

- Search/list tests:
  - Explicit disallowed folder search behaves like not found/empty as designed.
  - Search results never include disallowed folders.
  - All-folder search only iterates allowed folders.
  - All-mail/archive heuristic never selects a disallowed folder.

- Direct access tests:
  - `mail_fetch(ids=[...])` to a disallowed folder behaves like not found.
  - Text/html/raw resources for disallowed folders behave like not found.
  - `mail_download_attachment` and `mail+attachment://...` for disallowed folders behave like not found.
  - `mail_debug_list_parts` cannot bypass policy.

- Cache tests:
  - Cached message from a newly disallowed folder is not returned.
  - Cached message whose stored `folder_path` mismatches requested token is not returned.
  - Allowed cache hits still work.

- Protocol-specific tests:
  - IMAP still uses readonly select and `BODY.PEEK` in all fetch paths.
  - POP3 denies non-INBOX tokens and respects exclusion of `INBOX`.
  - Graph direct fetch rejects folder-token/message parent mismatch.
  - Graph raw and attachment fetches verify parent folder before returning bytes.

## Acceptance Criteria

- All listed access paths enforce current folder policy before returning any folder/message/body/raw/attachment data.
- Cache cannot bypass policy.
- Denied access is logged internally but presented as missing/not found externally.
- Test suite covers allow-list, exclude-list, case-insensitive exact matching, cache bypass prevention, and direct access/resource bypass prevention.
